# Graphics driver selection

Freshkit's Drivers action and setup driver stage detect present PCI display adapters. AMD graphics use `amd-software-adrenalin-edition`; NVIDIA uses `geforce-game-ready-driver` (NVIDIA's unaltered installer, which includes a complete NVIDIA App; the stripped `nvidia-display-driver` package left the App without its backend components); reviewed Intel Arc and Core Ultra graphics use `intel-arc-graphics-driver`. Each package appears once on hybrid systems. Driver packages are removed from the ordinary Apps plan so they pass through hardware selection, resume revalidation and machine registration checks.

AMD retains its existing vendor/class candidate check and Windows 11 requirement. The reviewed [Adrenalin package](https://community.chocolatey.org/packages/amd-software-adrenalin-edition) (26.10.2, reviewed 2026-11-15) downloads a Windows 11 executable from AMD. This check does not establish full AMD model/INF compatibility; older Radeon, workstation and OEM devices may require a different package. Match the device against [AMD's driver selector](https://www.amd.com/en/support/download/drivers.html) when preparing a machine with those devices.

Intel selection uses an explicit PCI device allowlist in `Drivers.Core.psm1`, covering consumer Arc A-series, B570/B580 and reviewed Core Ultra Series 1/2 graphics IDs. Windows 10 22H2 (build 19045) or Windows 11 is required. Unknown IDs, older Iris/UHD adapters and Pro devices receive manufacturer/OEM driver guidance. They do not receive the latest Arc driver automatically. A supported Intel device can still be selected on a hybrid system containing another Intel device outside this allowlist; the detection detail identifies that other device separately.

The [Intel driver download](https://www.intel.com/content/www/us/en/download/785597/intel-arc-graphics-windows.html) (32.0.101.9175 at review) lists Arc A/B and Core Ultra support, OS requirements, and the effect on OEM customizations. [Intel's device definitions](https://github.com/intel/compute-runtime/blob/master/shared/source/dll/devices/devices_base.inl) provide PCI IDs and product families. These were cross-checked with that Windows driver support list; an entry in the compute runtime alone is not evidence of Windows package compatibility. [Intel's driver selector](https://www.intel.com/content/www/us/en/support/articles/000090440/graphics.html) documents the separate older graphics branches.

The [Chocolatey Intel package](https://community.chocolatey.org/packages/intel-arc-graphics-driver/32.0.101.9175) downloads the Intel executable with checksum validation and runs its silent installer. Its title and description still mention older Iris Xe/Core products: use Intel's current compatibility list when updating the allowlist. The old `intel-graphics-driver` package is excluded from Apps too, but is not automatically selected as a fallback.

Installation success requires both the Chocolatey outcome and matching machine driver uninstall registration. A standalone Intel Graphics Software/control application does not verify the driver. Missing or unfamiliar registration is reported as `UnverifiedDriverInstall` for review. Registration confirms installation evidence, not hardware operation. Saved runs re-detect hardware before installing a queued driver and preserve package identity through retry and restart.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tests/drivers.ps1` for synthetic AMD/Intel/NVIDIA detection, hybrid systems, incompatible Intel branches, filtering, real stage result handling and continuation/reconciliation. External installers, registry reads, account checks and resume disk/task operations are replaced in this test. Real hardware installation and restart behavior still need a disposable Windows VM or a suitable test machine.

## Read-only driver preview

The driver preview reads present devices and `Win32_PnPSignedDriver`. It matches each signed driver's `DeviceID` to an exact device identity from the hardware inventory, including the PnP instance where available. Two cards with the same display name retain separate installed versions. Missing or conflicting signed-driver versions appear as `Unknown`.

Available versions come from the official Chocolatey community Atom feed, using an exact package ID and latest stable version filter. Each package is requested once per scan, with a four-second response/read timeout. The background scan process has a 45-second total limit. Offline, malformed, unrelated or unavailable metadata stays `Unknown`; it never becomes an “up to date” result. A Windows driver version and a package version are labelled separately because their numbering can differ.

Compatibility comes from the same existing candidate rules used by installation. The preview displays reasons and direct HTTPS links to known manufacturer support sites, falling back to the hardware vendor's selector or Microsoft's Device Manager guidance. A scan never requests elevation, installs packages, writes registry values or registers continuation tasks. Continuing an install remains an explicit action through the existing job engine.

`tests/driver-preview.ps1` exercises synthetic CIM and metadata responses; `tests/run-driver-preview.ps1` exercises the JSON model, version labels, unknown results and official support URL validation. The backend JSON uses `SchemaVersion: 1`, `InventoryComplete`, `Error`, `ScannedUtc` and per-device `Rows`; incompatible or incomplete schemas are rejected by the viewer.
